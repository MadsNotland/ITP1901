
# Teamwork (Release 3)

This release builds on our reflection from release 2. We maintained the planning structure that had proven effective; lightweight sprint planning using issues and milestones, but improved our coordination as the sprint progressed. In the final week, we held more frequent check-ins resembling Scrum stand-ups to ensure shared awareness and early detection of blockers. By aiming to complete the release on Friday instead of the Monday deadline, we established a buffer that reflects what we learned from earlier iterations, marking a shift in mindset from “rushing to deliver” toward “stabilizing and polishing.” This aligns with the Scrum value of maintaining a sustainable pace.

Workload distribution improved as we clarified ownership across areas such as server, testing, tooling, UI, and user stories. At the same time, we practiced collaborative learning through pair work on cross-cutting tasks, similar to the “rolling pairs” model discussed in lectures. This helped maintain collective code ownership and knowledge sharing while reducing context switching and dependencies.

Our workflow and technical collaboration also matured. We introduced a commit message template and continued using feature branches per issue, with pull requests and reviews as our formal quality gates. Code reviews became more deliberate, with reviewers pulling the latest branch and providing specific feedback on code clarity, testing, and design. Backend–frontend integration was notably smooth, thanks to early coordination on API design and transparent communication.

In summary, release 3 represents a move toward a more disciplined and sustainable Scrum-inspired workflow. Regular reflection, and improved review practices strengthened both our teamwork and the final product.
