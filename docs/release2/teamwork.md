# Teamwork 
So far, our team planning and coordination have been effective and steadily improving. We rely on regular meetings twice a week, each lasting two to three hours. Here we plan upcoming work and coordinate ongoing tasks. These meetings are also working sessions, allowing us to code together, engage in pair or group programming, and solve problems collaboratively. Outside the scheduled meetings, some members continue to collaborate in smaller groups, while others work individually. For quick updates or coordination needs, we use Facebook Messenger.

Task management is structured through GitHub Issues, Milestones, and the Project view with a Kanban board. Each release begins with a planning session where we define user stories (when relevant) and create all necessary issues. Milestones help us track progress, and tasks are self-assigned on a “first come, first serve” basis. This trust-based system has worked well, ensuring a fair workload distribution. We also keep documentation consistent by using templates for issues and pull requests, as well as following Conventional Commits.

Leadership in the group is not formally assigned, but naturally emerges depending on experience and personality. This flexibility has worked well, and since we have not encountered conflicts we have not requiring structural changes. A key lesson so far is the importance of fixed meeting times, which brings structure to the week and helps secure suitable working spaces. Working together in person has also been valuable, especially as we are still gaining experience with Git. Over time, we hope to become more confident in using the tools in Git and therefore not rely so much on physical meetings.
